The last rules a provider still kept for itself are the kernel's, and the kernel's deadline now covers the body.

**An address rule that only one provider had.** Test IT refused a `baseUrl` carrying a fragment; the other six folded one away in silence. A fragment never reaches the server, so what an operator pastes — the browser URL of the page they were reading — became an endpoint that meant something else, and the row looked accepted. The refusal now lives in `providers/kernel/address.ts` beside the credentials and query rule, with a knob for the one word a provider cannot share: an installation that legitimately has no certificate is called *internal*, not *development*, and the operator reading the refusal looks for the word their own product uses. Confluence, Test IT and Weblate resolve their lists through that policy now, so their three copies of `normalizeInstance` are gone; the row members a provider carries beyond the shared shape come from its own `extra`.

**One loop, and it owns the whole attempt.** `fetch()` resolves when the response headers arrive. The shared loop handed its caller an unread body, so the upstream decided how long the call lasted: answer `200 OK`, then dribble a few bytes a second, and the read — plus, in service mode, the rate-limiter slot leased around it — stayed open past every bound the deployment declared, because the size cap bounds bytes and not seconds. `fetchWithRetries` now takes a mandatory consumer and reads the body inside its own deadline; an attempt is not over until its body is. A consumer's verdict (too large, not JSON) is a decision about the payload, not a transport fault, and earns no further attempt. Confluence kept its own copy of the loop; the copy is gone, and with it the behaviour only it had — folding a timeout into `ProviderUnavailable`, so an operator could not tell a slow server from a dead one.

**Two retry budgets, named.** Where the shared loop bounds one read at `timeoutMs`, Jira and TeamCity re-sent a call they had timed out on, and one read cost `retries × timeoutMs`. The code was right and the comment was not: it described the other rule, which is how this survived review once already. `DEADLINE_IS_THE_BUDGET` and `RESEND_AFTER_EVERY_FAULT` are the kernel's two words for the choice, the default is the shorter one, and a provider names which it pays. Both sides are pinned by the same test on both providers — GitLab asserts one attempt after a timeout, Jira asserts the re-send — so the asymmetry stays a decision rather than an accident.

The client operator card kept one duplicate through its own split: `resourceRecord` was defined in `operator-sections/shared.tsx` and again in `service-profiles.tsx`. The shared one is kept. The kernel contract is now tested where it is written — `tests/kernel/`, the read-budget cases against a real socket rather than a hand-built `Response`, because the thing under test is whether an abort reaches a body still being read — and `scripts/verify-package.mjs` asserts the address and body rules on the kernel, instead of on whichever provider happened to hold a copy.

What is unchanged: the package's `exports`, the settings slot the card registers in, and the DOM the operator's tests read. Hence `patch` — no consumer of this plugin calls anything differently. What an operator can notice is that a stalled upstream now costs the timeout this deployment configured instead of an unbounded wait.
