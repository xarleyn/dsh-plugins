# Логирование DSH-плагинов

Механизм файлового логирования для плагинов: готовый пакет [`pino`](https://getpino.io)
+ пакет `@yadsh/dsh-plugin-log` с уровнями, ежедневной ротацией, ретеншном и
процессным реестром активных потребителей.

---

## 1. Принципы

- **Fail-open.** Логирование никогда не ломает плагин и хост: любая ошибка ФС
  или сериализации гасится, логгер деградирует до консольного зеркала.
- **Один runtime-пакет.** Серверные плагины зависят от
  `@yadsh/dsh-plugin-log`; локальные копии обёртки не создаются.
- **Стабильный API.** Экспорты пакета расширяются обратно совместимо.
- **Богатые файлы, тихая консоль.** Все уровни пишутся в файл в формате
  NDJSON или читаемого текста; в
  консоль хоста по умолчанию зеркалируются только `warn` и выше.
- **Безопасность.** Секреты, ключи и содержимое промптов не логируются;
  чувствительные идентификаторы сокращаются до вызова логгера
  (пример — `abbreviateSessionId` в dsh-kv-persist).

## 2. Почему pino

| Критерий | pino | winston | consola/debug |
| --- | --- | --- | --- |
| Структурированный NDJSON из коробки | ✅ | частично | ❌ |
| Уровни + числовые веса | ✅ 10…60 | ✅ | частично |
| Неблокирующая запись в файл без worker-потоков (`pino.destination`/sonic-boom) | ✅ | ✅ | ❌ |
| Цена на горячем пути | минимальная | высокая | минимальная |
| Child-логгеры, `redact` | ✅ | ✅ | ❌ |

Worker-based транспорты pino (`transport:`-опция, pino-roll) внутри
хост-процесса DSH не используются — только `pino.destination`.

## 3. Расположение и формат

```
<$DSH_HOME>/logs/<pluginId>/<YYYY-MM-DD>.log     # по файлу на локальный день
```

`$DSH_HOME` разрешается как `process.env.DSH_HOME`, иначе `~/.dsh`
(`resolveDshHome`). Каталог создаётся лениво, при первой записи.

Без UI-менеджера формат по умолчанию — `json`: каждая строка является
JSON-объектом:

```json
{"level":30,"time":1768471201234,"plugin":"dsh-kv-persist","module":"coordinator","msg":"kv.session.cold","sessionId":"a1b2c3"}
```

- `level` — числовой вес pino (trace 10 … fatal 60);
- `time` — epoch ms;
- `plugin` — id плагина; `module` — добавляется через `child(module)`;
- `msg` — стабильный код события (`kv.session.cold`); поля события — рядом.

Ключи `level`, `time`, `msg`, `plugin`, `module` зарезервированы — полям
события эти имена давать нельзя.

Формат `text` сохраняет те же данные в строке, удобной для чтения человеком:

```text
2026-08-30T12:34:56.789Z WARN  [dsh-kv-persist/coordinator] kv.session.cold sessionId="a1b2c3"
```

Формат можно задать при создании (`format: "json" | "text"`) или сменить
на лету через `logger.setFormat(...)` / `setPluginLogFormat(...)`. Переключение
влияет на новые записи. Уже открытый дневной файл до следующей ротации может
содержать строки обоих форматов.

## 4. Уровни

Обёртка: `trace | debug | info | warn | error | fatal | silent`.

Пользовательский конфиг плагина может оставаться трёхуровневым
(`debug | info | off`) и маппится на обёртку: `off → silent`. Пример —
`logging.level` в dsh-kv-persist (SPEC §36).

Переопределение без правки конфига (для отладки):

```bash
DSH_LOG_LEVEL=debug                        # все плагины
DSH_LOG_LEVEL_DSH_KV_PERSIST=trace         # конкретный плагин (id → верхнее подчёркивание)
```

Env-уровень работает, только если конфиг не задал уровень явно.

## 5. Консольное зеркало

По умолчанию `warn` и выше дублируются в консоль (`console.warn/error`).
Зеркало инъекцируется (`consoleSink`) — например, на `ctx.logger` хоста,
как в dsh-kv-persist: сообщения вида `[<pluginId>/<module>] <event> k=v`.
Отключается `console: "silent"`. Зеркало не зависит от файлового уровня:
`info`-событие, отфильтрованное порогом `warn`, в файл не попадёт, но
`warn`-зеркало сработает у любой записи `warn+`, прошедшей свой порог.

## 6. Ротация и ретеншн

- Ротация — по локальной дате: имя файла пересчитывается при каждой записи,
  дескриптор меняется атомарно, старый файл закрывается в фоне.
- Ретеншн — `retentionDays` (по умолчанию 14, `0` = хранить вечно): при
  открытии нового дневного файла удаляются `YYYY-MM-DD.log` старше окна.
- Запись буферизованная, неблокирующая (`sync: false`, `minLength: 0`);
  `flush()` — принудительный сброс, `close()` — сброс+закрытие (идемпотентно).

## 7. Отказоустойчивость и guard'ы

- Ошибка создания каталога/файла → файловый вывод отключается, одно
  диагностическое сообщение уходит в зеркало, плагин продолжает работать.
- Запись после `close()` — тихо игнорируется; `close()` повторно — no-op.
- Файлы не пишутся, если:
  - `DSH_LOG_DISABLED=1` (или `DSH_PLUGIN_LOG_DISABLED=1`), либо
  - `NODE_ENV=test` и `dir` не задан явно — unit-тесты не трогают реальный
    `~/.dsh`; тестам файлового поведения нужен собственный `dir` в tmp.
- `getPluginLogger` кэширует инстанс по `pluginId` + `dir`: повторное
  создание сервиса (перезагрузка конфига) переиспользует дескрипторы, а
  явный `level` в опциях обновляет порог кэшированного инстанса.
- Корневой логгер автоматически попадает в процессный реестр и удаляется из
  него при `close()`; `child()` отдельную регистрацию не создаёт.

## 8. API и подключение в плагин

```ts
import { createPluginLogger, getPluginLogger, resolveDshHome } from "@yadsh/dsh-plugin-log";

const log = getPluginLogger({
  pluginId: "dsh-my-plugin",      // обязателен; [A-Za-z0-9][A-Za-z0-9._-]*
  level: resolved.logLevel,       // опционален
  consoleSink: (level, message) => routeToHost(level, message),
});

log.info("my.event", { workspaceId: "w1" });
log.child("scanner").debug("my.scan.tick", { n: 3 });
await log.close();                // в dispose-пути плагина
```

Рецепт подключения (эталон — `plugins/dsh-kv-persist`):

1. Добавить `"@yadsh/dsh-plugin-log": "workspace:^"` в `dependencies`
   пакета плагина (при публикации pnpm заменит workspace-протокол версией).
2. Собрать фасад плагина поверх обёртки (в kv-persist —
   `src/observability/diagnostics.ts`): сокращение чувствительных полей —
   до вызова обёртки, маппинг `off → silent`, инъекция `consoleSink` на
   `ctx.logger`.
3. Закрыть логгер в dispose-пути (`await logger.close?.()`).
4. Клиентский (браузерный) код плагина логгер не импортирует — `node:*` и
   файлы недоступны в браузере.

## 9. Реестр активных потребителей

Любой корневой логгер, созданный через `createPluginLogger` или
`getPluginLogger`, обнаруживается без ручной регистрации:

```ts
import {
  getRegisteredPluginLoggers,
  setPluginLogFormat,
  setPluginLogLevel,
  subscribePluginLoggerRegistry,
} from "@yadsh/dsh-plugin-log";

const current = getRegisteredPluginLoggers();
// [{ registrationId, pluginId: "dsh-kv-persist", dir, level: "info", format: "text" }]

const unsubscribe = subscribePluginLoggerRegistry((snapshot) => {
  renderLoggingSettings(snapshot);
});

setPluginLogLevel("dsh-kv-persist", "debug"); // число обновлённых инстансов
setPluginLogFormat("text");                    // все активные логгеры
unsubscribe();
```

Подписчик сразу получает полный snapshot, затем новые snapshot'ы при создании,
закрытии и смене уровня. Ошибки подписчиков гасятся. Реестр хранится на
`globalThis` под `Symbol.for(...)`, поэтому остаётся единым при нескольких
физических копиях пакета в одном Node-процессе. Это runtime-discovery: плагин,
который ещё не загрузился или уже вызвал `close()`, в списке отсутствует.

Пакет публикуется отдельно от плагинов, потому что входит в runtime-зависимости
их npm-тарболлов. `dsh-kv-persist`, `dsh-doc-impact` и генератор новых плагинов
уже используют пакет вместо локальных копий.

Плагин `@yadsh/dsh-plugin-log-ui` использует этот реестр и добавляет карточку
**Plugin logging** в **Settings → Plugins → Plugin Configuration**. В ней
задаются общий уровень, override для каждого обнаруженного `pluginId` и формат
`text`/`json`. Настройки применяются без рестарта и к уже активным, и к позднее
зарегистрированным логгерам. Его default — `info` + `text`.

## 10. Анти-паттерны

- `pino(...)` с worker-транспортами (`transport:`-опция) — лишние потоки в
  хост-процессе.
- Логирование в клиентском бандле плагина.
- Секреты/ключи API/полные тексты промптов в полях событий.
- `throw` из пользовательского `consoleSink` — ломает чужой поток логов
  (обёртка это гасит, но так делать не нужно).
- Прямые `console.log` в host-коде плагина в обход обёртки.
